AI Data Center Hardware Explained: DDR5 ECC RAM, HBM GPU Memory & NVMe SSDs

A cloud AI system does not run on one “AI chip.” Inside its servers, CPUs, system RAM, GPU accelerators, high-bandwidth memory, enterprise SSDs and networking each perform different jobs. This visual guide explains exactly where data lives, which memory types are used, how they interact and how much memory a model may need.

Quick answer: A typical large AI server can have CPU-attached ECC DDR5 RDIMMs for host operations, HBM3e or another accelerator-specific high-bandwidth memory beside its GPUs for active model computation, and NVMe SSDs for persistent datasets, model files and checkpoints. These are different layers—not different names for the same RAM.

1. What happens when you ask cloud AI a question?

Your request travels to a hosted AI service. The server's CPU handles parts of the application and coordination, while its AI accelerator executes the model's numerical operations. Model files may be loaded or staged from storage into memory; the active weights and intermediate values needed by GPU inference generally live in accelerator memory. The generated output then returns through the application to your device.

Not every AI request takes the exact same path. Some smaller models run entirely on a laptop CPU, mobile NPU or integrated GPU; large hosted language models often run on distributed accelerators. For the foundations, see how AI models use chips.

2. Which RAM does the CPU use? DDR5 ECC RDIMM explained

DDR5 is a generation of dynamic random-access memory (DRAM). RDIMM refers to a registered DIMM design used in compatible servers to support reliable high-capacity memory configurations. ECC means error-correcting code: compatible hardware can detect and correct certain memory errors.

Host RAM holds operating-system data, data loaders, preprocessing pipelines, application memory, CPU-side buffers and other processes. It is generally volatile—its data is not retained like SSD files after loss of power.

Older data centres may still use DDR4 ECC RDIMMs. Modern systems commonly use DDR5 ECC RDIMMs, while some CPU/platform combinations support higher-bandwidth MRDIMMs. Lower-power options such as LPDDR5X-based SOCAMM also exist in certain architectures; they are not universal replacements for standard server DIMMs. All memory upgrades must match the CPU and platform's supported configuration.

Micron's data-centre memory documentation discusses DDR5, MRDIMM, HBM and other form factors. It identifies MRDIMM as a high-bandwidth main-memory option on compatible Intel Xeon platforms.

3. Which RAM does an AI GPU use? HBM3, HBM3e and newer HBM

HBM stands for High Bandwidth Memory. HBM places multiple DRAM dies in stacked structures near the processor through advanced packaging, delivering high memory bandwidth for workloads such as neural-network matrix operations. Modern GPU accelerators may use HBM3, HBM3e or newer HBM generations depending on the product; not all AI accelerators use the same HBM type.

GPU-attached memory typically holds model weights being used, activations and intermediate buffers, plus inference data structures such as the KV (key/value) cache for attention-based models. High bandwidth helps feed arithmetic units efficiently. GPU memory capacity also limits how much model state and how many concurrent requests fit without offloading or distributing data.

For example, NVIDIA lists 180 GB HBM3e per B200 GPU and 288 GB per B300 GPU in its reference-architecture documentation. Those figures should not be confused with host DDR5 system RAM. See NVIDIA's GPU-memory specifications.

Important: The fastest type is not automatically the most suitable. HBM is expensive high-throughput working memory; SSDs store much larger volumes persistently. A 100 GB model file on SSD does not mean 100 GB of GPU memory is already available for inference.

5. Which SSDs are used in AI data centres?

Enterprise AI servers commonly use NVMe SSDs because NVMe communicates efficiently over PCIe and supports high throughput and parallel access. SSDs do not perform the model's calculations; they hold the files needed by the system and help load data fast enough to avoid starving accelerators.

6. What is physically inside an AI server?

An AI server may include one or more CPUs, many DIMM sockets, several GPU accelerators, high-speed interconnects, local SSDs, network cards, baseboard management controllers, redundant power supplies and powerful cooling. The arrangement differs substantially between server models. GPUs may connect through PCIe, NVLink or purpose-built backplanes, and the system may use air or liquid cooling.

Because training and inference can use many machines, the broader data centre also needs networking, shared storage, electricity distribution, monitoring, security controls and cooling infrastructure.

7. Real-world example: NVIDIA DGX B200 specifications

According to the official NVIDIA DGX B200 User Guide, the following configuration is published for the DGX B200 system. These are system specifications, not specifications for every AI data centre.

Do not add system RAM to GPU memory and present the sum as a single pool of GPU working memory. The GPU total is spread across separate devices; applications need appropriate model parallelism, communication and runtime support to use memory across accelerators.

Storage maths: 8 × 3.84 TB = 30.72 TB of manufacturer-rated raw cache-drive capacity. RAID 0 stripes data but does not provide drive-failure redundancy; filesystem and reserved-space overhead also affect usable capacity. A two-drive RAID 1 boot set has roughly one drive's logical capacity before filesystem overhead.

8. What changes with NVIDIA DGX B300?

NVIDIA's DGX B300 User Guide describes eight B300 GPUs with 288 GB GPU memory each (2,304 GB total by arithmetic), default 2 TB system RAM (up to 4 TB), 8 × 3.84 TB E1.S NVMe cache SSDs and 2 × 1.92 TB M.2 NVMe boot SSDs. Unlike the B200's U.2 cache drives, B300 uses E1.S for that internal cache configuration.

This B200-versus-B300 comparison shows why precise model names matter. Memory technologies, SSD form factors and CPU platforms evolve; never assume every generation uses identical parts.

9. Mathematics: how much RAM does an AI model need?

A simple starting estimate for model-weight storage only is:

Raw model weights (bytes) = parameter count × bytes per parameter

Take a hypothetical model with 70 billion parameters. At 16-bit storage, one parameter takes 2 bytes. The raw weight data requires:

70,000,000,000 × 2 = 140,000,000,000 bytes = 140 GB

At an ideal 4 bits per parameter (half a byte), the lower-level theoretical weight data is:

70,000,000,000 × 0.5 = 35,000,000,000 bytes = 35 GB

Decimal versus binary: These figures use decimal gigabytes (1 GB = 109 bytes). In binary units, 140 GB is about 130.4 GiB, and 35 GB is about 32.6 GiB. Real 4-bit formats require additional scales, metadata or padding, so their actual stored size can exceed the ideal 35 GB.

Crucial limitation: Raw model weights are not the whole memory requirement. During inference, software can need temporary buffers, KV cache, model metadata and framework overhead. Training may additionally need gradients, optimizer states and activations. Large models can be split across multiple GPUs, or partially offloaded, but that changes performance characteristics.

One H200 has 141 GB HBM3e, so does a 140 GB weight file always fit? No. Even before differences between GB and GiB, actual inference needs overhead beyond weights. You must measure the model's complete working set and the inference runtime's memory allocation.

10. How do datasets and weights move from SSD to RAM and GPUs?

  1. Persist: model checkpoints, datasets and executable files are kept in enterprise SSDs or shared storage.
  2. Read: the storage subsystem moves required data into memory through software and I/O pathways.
  3. Prepare: CPU-side software may decode, batch, tokenize or transform data using system RAM.
  4. Stage: tensors and model parameters reach the accelerator's working memory, possibly through specialised paths.
  5. Compute: the GPU or accelerator processes operations using local memory and communicates with other accelerators when necessary.
  6. Save: in training or fine-tuning, checkpoints are written back to persistent storage.

The exact path varies with hardware and software: GPUs can in some systems participate in direct storage transfers, and applications may use caching or memory-mapping. The simplified diagram is a learning aid rather than a universal wiring diagram.

11. RAM and SSD also affect electricity and cooling

AI server power does not come only from GPU chips. CPU sockets, memory modules, SSDs, networking adapters and cooling equipment also draw power. More memory capacity or faster I/O can change total system power, even if it reduces training delays or improves accelerator utilisation.

The total facility impact depends on real workload draw and data-centre overhead—not simply the sum of component datasheet maxima. The companion AI chip electricity and water article explains energy in kWh, facility PUE and site WUE with properly scoped examples.

12. What should you check when comparing AI-server specifications?

  • Model and workload: training, inference or a smaller CPU-only task?
  • GPU memory: per-GPU capacity, memory bandwidth, total accelerators and communication links.
  • Host memory: total DDR5 ECC RAM, supported DIMM speeds, channel configuration, upgrade limits.
  • Storage: boot versus cache drives, NVMe generation, SSD endurance, protection and shared storage.
  • Networking: speed and topology for multi-GPU or multi-node training.
  • Operations: power envelope, cooling method, redundancy and management features.

Frequently asked questions

Does AI use normal RAM or special RAM?

Both. CPUs can use ECC DDR5 system memory, while many AI GPUs use HBM for high-bandwidth working memory. Their jobs differ.

Is DDR5 RAM faster than HBM3e?

They have different designs and intended uses. HBM typically provides far greater total bandwidth close to large accelerators, while DDR5 provides flexible system memory for CPUs. Direct comparisons require platform-specific capacity and bandwidth figures.

Can I run AI with only a regular SSD and 16 GB RAM?

You can learn machine learning and run appropriately small CPU-based models, depending on your CPU, available memory, model size and other applications. Storage capacity alone does not guarantee that a large model can run.

Does 1,440 GB total GPU memory mean a single 1,440 GB pool?

No. The B200 figure sums memory across eight GPUs. Using it for one model requires suitable distribution and software; not every program can automatically use all of it.

Are NVMe SSDs more important than HBM?

They serve different purposes. Fast SSDs help load and retain large datasets and models, whereas HBM supplies active accelerator computation. Effective AI systems need an appropriate balance.

Does storing a model on an SSD mean it uses no GPU memory?

No. During ordinary GPU inference, working model data and intermediate values require GPU memory or a designed offload strategy. An SSD is persistent storage, not a replacement for all GPU RAM.
