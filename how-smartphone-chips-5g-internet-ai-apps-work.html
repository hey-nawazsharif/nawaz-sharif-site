Inside a Smartphone: How Chips, 4G/5G Internet and AI Apps Really Work

A modern phone can stream videos, show a website over 5G, take professional-looking photographs and answer questions using AI. But which chip actually makes the internet connection? What does the SIM do? Where does an AI model run—in the phone or inside a data centre? Follow a real-world request from a tap on your touchscreen to the network and back, then test the concepts yourself.

The short answer: A phone has an application processor (often a system-on-chip, or SoC), working memory, persistent storage, radio hardware and a battery. The cellular modem and antenna connect to a mobile operator through 4G/5G; the Wi-Fi radio uses a local access point instead. An AI app may run a small model on the phone's CPU/GPU/NPU, send a request to a remote AI server, or combine both. An “AI” icon does not reveal which processing method the app uses.

1. What is actually inside a smartphone?

A smartphone is a compact computer plus multiple wireless systems. Behind the screen are processor chips, LPDDR working memory, flash storage, radio-frequency circuits, antennas, image sensors, power management and a battery. Different manufacturers may integrate more or fewer functions into the same package.

The SoC (system-on-chip) often integrates multiple processing functions. Qualcomm describes Snapdragon platforms with CPU, GPU, NPU and modem capabilities, although not every version integrates the modem physically on the same die. Qualcomm — What is Snapdragon? The exact design for any phone depends on its model.

2. CPU vs GPU vs NPU vs modem: why are there different chips?

These components solve different problems. The CPU handles flexible code and operating-system tasks. The GPU handles graphics and large amounts of parallel computation. The NPU runs supported neural-network operations efficiently. The modem is specifically responsible for communicating over mobile radio networks. The SIM is not the modem and an NPU is not a cellular transceiver.

For example, a modern Snapdragon 8 Elite Gen 5 platform has an application processor and dedicated AI/modem capabilities, but a phone's realised features also depend on its antenna system, device software, carrier bands and manufacturer choices. Similar principles apply to other smartphone chip families, including Apple and MediaTek designs.

Important engineering distinction: A phone can have an extremely powerful NPU yet still need a mobile modem or Wi-Fi hardware for Internet access. Conversely, a phone can connect to 5G and use a cloud AI app even when its local NPU is not running that model.

3. What does a physical SIM or eSIM actually do?

A SIM or eSIM holds subscription credentials and information used to identify and authenticate a customer to a mobile network. A physical SIM is a removable card; an eSIM is a remotely provisionable subscriber profile on compatible embedded SIM hardware (eUICC). The SIM is not where internet pages are stored, and it does not provide the phone's actual radio signal.

When the phone registers, its modem and the mobile operator exchange signalling; the subscription is authenticated by the operator's systems before service is authorised. The network then establishes the appropriate data connection. The detailed authentication and network-control steps differ between generations and carrier deployments. Android Open Source Project — eSIM overview; GSMA — Securing the 5G era.

Easy analogy: A SIM helps prove who is allowed to use the mobile network. The modem and antennas are the equipment that communicate. The operator infrastructure provides the route toward the internet. Real cellular security involves more than that analogy, but it keeps the roles separate.

4. How does 4G/5G Internet actually work?

Imagine typing a website address while mobile data is enabled. The app asks the operating system for network access. The phone's modem sends encoded radio signals through its antenna to an available cell site. The operator's backhaul and core network authenticate sessions, route packets and connect them to internet services. The reply follows a network route back to the device.

  1. Choose a mobile connection: The phone finds a supported operator radio cell and exchanges registration and network messages.
  2. Authenticate: Subscriber credentials from SIM/eSIM participate in the operator's network authentication.
  3. Establish data connectivity: Network functions allocate connectivity parameters and make a data route available to the phone.
  4. Send packets: The modem transmits radio signals; the cell station and operator's infrastructure carry data toward the destination.
  5. Reach the service: A website, video platform or AI API responds to the application's request.
  6. Receive and render: The phone receives data; the operating system and app show the result on screen.

4G and 5G are not one universal route. LTE normally uses a 4G evolved packet core. A 5G Non-Standalone (NSA) setup can use 5G radio with an existing 4G core. 5G Standalone (SA) uses a 5G radio access network with a 5G core. The user-facing “5G” icon alone does not prove which architecture serves a request. GSMA — 5G Standalone and GSMA — 5G NSA.

5. Wi-Fi versus 4G/5G: what actually changes?

Wi-Fi also uses radio waves, but it normally connects to a nearby access point or router, which reaches the internet through broadband or another upstream connection. Mobile data connects to a mobile operator's cellular radio network, typically using a SIM/eSIM subscription. The website or AI cloud server can be identical in both cases.

Switching between Wi-Fi and cellular can change network latency, bandwidth, IP routing, data charges and battery use, but it does not automatically move a remotely hosted AI model onto the phone. Devices and apps may keep or reestablish connections during network switching.

6. Where do DNS and HTTPS fit when you open a website?

A browser or app typically needs to resolve a domain name to a usable network address. DNS helps obtain such address records, often using caches or a configured resolver. The client then connects through the network to the chosen service. HTTPS uses Transport Layer Security (TLS) to protect the web/application communication in transit.

Your tap → app / OS → network route → DNS (if needed) → HTTPS connection → web/API server → response

DNS and HTTPS solve different problems. DNS answers where to connect; HTTPS protects the application session. The network operator still must route packets and may observe some network metadata. HTTPS does not mean every app stores your data privately or that the endpoint cannot read the request it is meant to process. Cloudflare — DNS explained and Cloudflare — TLS handshake.

The complete process can be optimised with DNS caching, connection reuse, content-delivery networks or encrypted DNS. Consequently, the exact network packets sent for two seemingly identical user actions need not be the same.

7. Internet speed explained with simple, practical mathematics

Network speeds are commonly advertised in megabits per second (Mb/s or Mbps), while file sizes often use megabytes (MB). Eight bits make one byte. To avoid confusing the units:

Theoretical maximum MB/s = Mbps ÷ 8

Suppose a connection sustains 100 Mbps. The ideal payload-equivalent transfer rate is 12.5 MB per second. An illustrative 25 MB file would require at least:

25 MB ÷ (100 ÷ 8) MB/s = 2 seconds (ideal)

This is a lower-bound arithmetic illustration, not a download guarantee. Actual time can be longer because of protocol overhead, encryption setup, radio variability, congestion, connection limits and server performance. Marketing “up to” rates and momentary speed tests are not sustained file-transfer measurements.

Latency is different from bandwidth. A connection can download large files rapidly yet take longer to start an interactive response. AI chat responsiveness depends on network latency and queue time, model computation, generated-token rate and application rendering.

Practical thought experiment: Two phones both show “5G,” but one is near a busy tower and the other has stronger radio conditions and less congestion. Their response times can differ even if both have the same NPU. That is a network-performance difference, not necessarily an AI-chip difference.

8. What happens when you ask a cloud AI app a question?

Suppose an AI app is configured to use a remote cloud model. You type a question, attach an image or speak. The application converts your input into a suitable request and sends it over its network connection to the provider's infrastructure. The remote model performs inference on server hardware—often using GPUs or other accelerators—and generates an output that the app presents on screen.

  1. Input: The touchscreen, microphone or camera provides data to the application, subject to permissions.
  2. App and OS: The processor and memory handle local UI, formatting, buffering and security functions.
  3. Network: The app uses Wi-Fi or mobile data to reach an authorised service, generally using HTTPS.
  4. Cloud inference: The server applies a trained model to the input and generates a result.
  5. Response: The phone receives text or other data, and its CPU/GPU renders the output.

Cloud-based ChatGPT-style and Gemini-style interactions commonly follow this high-level model, but particular products may also use local pre-processing, system integrations or hybrid features. The location of processing depends on the product and feature, not merely the app's brand name.

9. What does “on-device AI” mean, and what is an NPU?

On-device inference means the trained model executes on the phone itself—possibly using its CPU, GPU, NPU or some combination. The model weights and relevant runtime are accessible locally, and the data needed for that operation can stay on the device when the application is designed that way.

The NPU is designed to accelerate supported machine-learning operations with good energy efficiency, but it does not magically make all installed AI apps process every prompt locally. For a particular model, its runtime and available hardware determine whether computation uses an NPU, GPU or CPU.

Google's modern Android guidance describes LiteRT and other tools for on-device ML, as well as cloud-based choices. The older Android Neural Networks API (NNAPI) was deprecated in Android 15, so developers should check current recommended runtimes rather than treating NNAPI as the universal present-day solution. Android Developers — AI options; LiteRT on Android; NNAPI migration.

10. Hybrid AI: why some phones use both local models and cloud servers

Local processing can reduce network dependence and limit the need to transmit certain data, while cloud servers can run models that are too demanding for a mobile device or support service-specific features. A hybrid system can decide which tasks run locally and which require remote computing.

Apple documents Apple Intelligence workflows in which many tasks run on-device, while more demanding operations can use Private Cloud Compute on supported devices. These are Apple's published design claims about its own system and should not be assumed to apply to every third-party AI app. See Apple — Intelligence and privacy on iPhone and Private Cloud Compute security guide.

On Android, different applications can use local frameworks or cloud APIs depending on their design. Some on-device features operate offline after models are installed, but account login, model downloads or optional online capabilities may still require internet. “Runs on-device” is a feature-specific technical statement, not proof that an entire application never contacts a server.

11. How much phone memory might a local AI model need?

As a rough starting point, the raw storage for model weights depends on the number of parameters and bytes per parameter. Real memory use includes temporary tensors, cache, framework overhead and other active applications.

Raw model weights (bytes) ≈ parameters × bytes per parameter

For an illustrative model of 3 billion parameters, ideal 8-bit weights require approximately 3 GB of raw data (3 billion × 1 byte). Ideal 4-bit weights require approximately 1.5 GB (3 billion × 0.5 byte). Actual quantised formats include scales, metadata and padding, so files and runtime memory can be larger.

A phone with 8 GB of system RAM does not necessarily have 8 GB free for an AI model. The operating system and apps are already using memory, and GPU/NPU memory access arrangements differ by platform. A larger model may require extra capacity, partitioning or cloud processing.

The same principle extends to GPUs in AI data centres, but mobile shared-memory designs should not be confused with server-grade HBM. For a deeper comparison, see our AI data-centre RAM and SSD guide.

12. Five safe experiments you can try on your own phone

You do not need special diagnostic equipment, rooting, a paid API or access to carrier infrastructure to explore these concepts. Observe ordinary phone settings and app behaviour; avoid handling private login codes or running questionable test applications.

  1. Observe Wi-Fi versus mobile data. Open your phone's network settings. Visit a public website on Wi-Fi, then, if you have a data allowance, switch to cellular and repeat. Note whether the page loads and how the connection changes. Do not assume the site's content changed.
  2. Test a download-speed estimate. If a network tool displays an average of 80 Mbps, divide by eight: the ideal rate is 10 MB/s. A hypothetical 20 MB file would take at least two seconds under steady conditions. Compare with a real transfer while remembering protocol overhead.
  3. Try an offline-capable AI feature. Use only a feature explicitly documented as on-device and offline-capable on your model. Download any required models first, then disconnect internet access and test. If it works, the relevant operation can be local; if it fails, the cause could be licensing, setup or other online dependencies.
  4. Observe DNS versus website availability. Learn what DNS does through a trusted explainer rather than altering sensitive network settings. A web address identifies a service, and DNS helps locate its network address; encryption and page rendering happen at other layers.
  5. Review app permissions. On iPhone or Android, inspect camera, microphone, location and cellular-data permissions for an AI app. An app showing a chatbot screen does not automatically need all those permissions.

iPhone and Android menu names vary by OS version, device manufacturer and region. Airplane mode may allow Wi-Fi to be switched back on, so verify that all internet connectivity is actually disconnected for an offline test. Switching off mobile data on a metered plan can also help avoid accidental charges.

13. Security, privacy, data usage and phone battery

For cloud AI, the server needs enough request data to process the feature. The provider's retention, training, privacy and access policies remain important—even when transport is encrypted. On-device AI can avoid sending selected inputs for remote inference, but it is not a universal guarantee that an app never collects analytics or contacts another service.

  • Protect the device: Keep the operating system and apps updated, use a strong unlock method and install from trusted sources.
  • Keep network security separate: Cellular network authentication, encrypted HTTPS sessions and an app provider's data-handling choices are distinct security layers.
  • Check permissions: Camera, microphone, photos and location access should match what the feature actually needs.
  • Watch data and battery: Large uploads, video and cloud AI traffic may use mobile data. Weak cellular signal, high screen brightness and intensive local AI can affect battery life; the impact varies by device and workload.
  • Be sceptical of “5G + AI” labels: They describe capabilities, not proof of high connection speed, local model execution or strong privacy.
Privacy clarity: Neither a VPN nor HTTPS automatically makes all internet activity invisible to every network participant. Encryption reduces exposure of protected content in transit, while IP routing, DNS configuration, account metadata and the service endpoint can still matter.

14. Common myths about phone chips, mobile internet and AI

  • “The SIM gives the phone internet.” It helps authenticate a mobile subscription; the modem, cell network and operator routing carry data.
  • “The CPU chip is the 5G tower receiver.” Cellular data involves a modem and RF hardware, integrated or separate from the application SoC.
  • “Every AI app is powered by my phone's NPU.” Cloud AI requests may be inferred on remote servers.
  • “More RAM always gives faster 5G.” Radio conditions, modem, bands, congestion and upstream networks are major factors.
  • “5G always beats Wi-Fi.” Actual throughput and latency depend on local conditions and network paths.
  • “Offline AI never uses the internet.” A specific model operation may be local, even while downloads, updates or account features use internet.
  • “100 Mbps means downloading 100 MB every second.” Bits and bytes differ by a factor of eight, before overhead.
  • “HTTPS means the AI provider cannot read my request.” HTTPS protects network transit; the destination service must usually process the submitted data.

Frequently asked questions

Which phone chip actually connects to 5G?

The cellular modem with radio-frequency circuits and antennas handles the cellular connection, supported by operating-system and application software. A SIM/eSIM helps authenticate the subscription.

Does an NPU make the phone's internet faster?

Not inherently. An NPU can accelerate supported machine-learning workloads. Internet speed primarily depends on the network path and radio/modem capabilities, although specific devices may use AI-assisted radio optimisations.

Can an AI app work without mobile data or Wi-Fi?

Only if the needed AI model and runtime are local and the feature does not require online services. Many chat apps require a cloud connection.

What is the difference between 5G NSA and 5G SA?

NSA can combine 5G radio with a 4G core, while SA uses 5G radio with a 5G core. The network provider and phone determine the deployment path.

Is an eSIM faster than a physical SIM?

Neither form factor automatically determines data speed. Supported modem/radio capabilities, subscription, network conditions and carrier configuration matter.

Is 8 GB RAM enough to run a local language model?

It depends on the model size, quantisation, available memory, OS overhead and runtime. Raw weights alone do not determine the memory needed to run a feature.

Is ChatGPT stored inside my phone?

The app and some local data can be installed on a phone, but cloud-served model inference runs remotely. Whether particular features use on-device processing depends on their implementation.
