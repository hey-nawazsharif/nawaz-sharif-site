Machine Learning for Cybersecurity: Anomaly Detection with Python

Suppose a system usually sees one or two failed sign-ins per ten minutes, but a new window suddenly includes dozens of failures and a surge in requests. How can we identify unusual behaviour without writing a rule for every possible pattern? This hands-on tutorial introduces anomaly detection using Python and scikit-learn's Isolation Forest.

This is Part 3 in a beginner series. Start with machine learning foundations or try Part 2: a supervised spam classifier first.

What you will build
  • Project: A local, read-only anomaly-scoring demo for fictional authentication activity
  • Level: Beginner to intermediate; basic Python helpful
  • Tools: Python, NumPy and scikit-learn (free, no GPU or cloud account)
  • Data: Generated in code — no real logins, accounts, IP addresses or workplace logs
  • Important limitation: An unusual event is not proof of an attack
01 / The idea

What is anomaly detection in cybersecurity?

Anomaly detection tries to find observations that differ from a baseline. Security teams might investigate unexpected sign-in volumes, unusual access times or sudden traffic changes. These patterns are signals to review, not automatic findings of malicious activity.

Unlike our spam-classification tutorial, this exercise does not require a spam/not-spam-style label for each training row. Instead, we fit a model on synthetic baseline activity and then score separate windows.

Why Isolation Forest?

IsolationForest builds randomised trees to isolate observations. Points that can be isolated in fewer splits tend to be more unusual. In scikit-learn, predict() returns -1 for an outlier and 1 for an inlier; the decision_function() produces lower scores for more anomalous rows.

Think of it as prioritisation, not a verdict. A legitimate maintenance job, changing user population or a broken application can also produce abnormal activity. Analysts need context and supporting evidence.

02 / Choose signals

Represent activity as features

We will represent each invented ten-minute time window using four numerical features. They are deliberately simple so you can understand the algorithm; they do not represent a production-grade detection design.

FeatureMeaning in this demo
failed_loginsNumber of failed authentication attempts
source_ipsCount of distinct source addresses (not the addresses themselves)
night_actionsCount of activity events in an invented off-hours period
request_countNumber of requests in the window

Real environments require better feature engineering, time-zone handling, identity and device context, privacy safeguards and validation against representative historical data. We intentionally avoid collecting any of that here.

04 / Hands-on Python lab

Complete working example

The script generates 400 normal training windows, a separate set of 100 normal test windows and eight intentionally extreme test windows. The eight labels are used only for evaluation, not to train Isolation Forest.

"""Synthetic authentication activity: educational anomaly detection only."""
import numpy as np
from sklearn.ensemble import IsolationForest
from sklearn.metrics import confusion_matrix, precision_score, recall_score

rng = np.random.default_rng(42)

def normal_activity(n):
    """Invented ten-minute windows, not production log records."""
    failed_logins = rng.poisson(lam=1.3, size=n)
    source_ips = rng.integers(1, 4, size=n)
    night_actions = rng.binomial(n=4, p=0.18, size=n)
    request_count = rng.poisson(lam=28, size=n)
    return np.column_stack([
        failed_logins, source_ips, night_actions, request_count
    ])

# Train on a simulated normal baseline; keep evaluation rows separate.
train_normal = normal_activity(400)
test_normal = normal_activity(100)

# Intentionally extreme invented windows for demonstration.
test_unusual = np.array([
    [35, 15, 18, 180],
    [23, 14, 10, 145],
    [42, 25, 12, 220],
    [17, 12, 25, 155],
    [29, 19, 9, 130],
    [48, 31, 30, 260],
    [18, 16, 15, 120],
    [32, 22, 22, 200],
])

X_test = np.vstack([test_normal, test_unusual])
# Labels are for evaluation, not for training the model.
y_true = np.array([0] * len(test_normal) + [1] * len(test_unusual))

model = IsolationForest(
    n_estimators=150, contamination=0.03, random_state=42
)
model.fit(train_normal)

# scikit-learn: -1 = outlier, +1 = inlier.
y_pred = (model.predict(X_test) == -1).astype(int)
scores = model.decision_function(X_test)  # Lower = more anomalous.

print("Evaluation windows:", len(X_test))
print("Confusion matrix [normal, unusual]:")
print(confusion_matrix(y_true, y_pred, labels=[0, 1]))
print("Precision:", round(precision_score(y_true, y_pred, zero_division=0), 3))
print("Recall:", round(recall_score(y_true, y_pred, zero_division=0), 3))

feature_names = [
    "failed_logins", "source_ips", "night_actions", "request_count"
]
print("\nFlagged examples (up to five):")
for i in np.where(y_pred == 1)[0][:5]:
    details = dict(zip(feature_names, X_test[i].tolist()))
    print(f"Window {i}: score={scores[i]:.3f}, features={details}")

print("\nThis tutorial does not establish that any event is malicious.")

How to read the code: np.random.default_rng(42) makes synthetic generation reproducible. fit() uses only the baseline rows. predict() flags unusual rows, and decision_function() provides a score. Our true labels allow us to calculate evaluation metrics on this artificial example.

05 / Interpret the result

What the local test shows

With the shown random seed and tested code, the evaluation produced these synthetic demonstration results:

Evaluation windows: 108
Confusion matrix [normal, unusual]:
[[96  4]
 [ 0  8]]
Precision: 0.667
Recall: 1.0

In the matrix, rows correspond to the invented true categories and columns to model predictions. Of 100 ordinary test windows, four were flagged even though they were not deliberately unusual. All eight extreme windows were flagged. Thus, 12 windows were flagged overall; only eight were the injected unusual examples.

Precision asks: among the flagged windows, how many were injected unusual cases? Here, 8/12. Recall asks: of the eight injected unusual cases, how many were flagged? Here, 8/8. Neither number demonstrates real-world attack-detection performance: the anomaly examples were intentionally easy and the data distribution was invented.

Do not report this as a production 100% detection rate. Security labels are complex, adversaries change tactics, benign behaviour changes, and operational costs from false alarms matter.

06 / Avoid common mistakes

What beginners should not overlook

  • Anomaly does not equal attack: prioritise review and evidence, not automatic account blocks or process termination.
  • Thresholds are a trade-off: contamination=0.03 sets a training-score cutoff roughly corresponding to a 3% outlier fraction; it is not a statement that 3% of real traffic is malicious.
  • Baseline quality matters: the model will learn whichever patterns are present in the data used for fitting, including mistakes or suspicious behaviour.
  • Separate evaluation data: avoid choosing a threshold after repeatedly examining the same test set; use proper validation and representative time-based evaluation before operational use.
  • Data privacy: real authentication logs can contain personal information, tokens or identifying metadata. Follow applicable policies and minimise collected data.
  • Concept drift: software upgrades, staff shifts and traffic seasonality can change what normal looks like; monitor and reassess performance over time.
07 / Your next experiment

How to extend the educational project

Change the normal request-volume distribution, introduce a subtle rather than extreme unusual pattern, or add weekly patterns. Track the confusion matrix after every change. Compare the isolation model against a transparent rule-based baseline, and write down when the model fails.

If you later study real operational monitoring, begin with permissions, privacy review and non-disruptive alerting. Never automatically act on an anomaly score alone. For a separate example focused on build pipelines, see anomaly detection in CI/CD pipelines.

Frequently asked questions

Is this AI or machine learning?

Isolation Forest is an unsupervised machine learning method, which is one approach within the wider AI field.

Do I need Kali Linux or a paid cloud service?

No. This Python example runs locally on an ordinary laptop with free libraries.

Will the script detect hackers on my computer?

No. It does not inspect your computer, access live logs or contact a network. It only classifies fictional numeric activity windows; it is a teaching exercise.

Can a low anomaly score prove a cyberattack?

No. It indicates the model considers an observation unusual relative to its learned baseline. Further context and investigation are required.
