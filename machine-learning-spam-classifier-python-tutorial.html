Build a Spam Classifier with Python: Your First Machine Learning Project

How does software distinguish a suspicious promotional message from an ordinary email? In this tutorial, you will train a small text classification model, test its predictions and learn why a good-looking accuracy score is only the beginning.

This is Part 2 of the beginner series. If features, labels and training sets are new to you, start with Machine Learning Explained: A Beginner's Guide.

At a glance
  • Level: Beginner with basic Python familiarity
  • Cost: Free; runs locally, no account or cloud GPU needed
  • Tools: Python 3, scikit-learn and a text editor
  • Project: Classify spam versus ham (normal messages)
  • Privacy: Uses only invented example messages
01 / Understand the project

How a text classifier works

A supervised model learns from examples that already have labels. Here, each training example contains a message and its label: spam or ham. When it receives an unseen message, it predicts the more likely label based on patterns it learned.

  1. Label examples
  2. Split data
  3. Convert words to numbers
  4. Train
  5. Evaluate

Two ingredients you will use

TF-IDF converts text into numerical features, placing weight on terms according to how informative they are across the training messages. Multinomial Naive Bayes is a simple probabilistic classifier frequently used as a baseline for text classification. It is fast and works well for small experiments, but is not guaranteed to be the best model.

We combine the two in a Pipeline. This matters because text features must be learned from the training portion only, not from the held-out test messages.

Install Python and scikit-learn

Save the Python script shown in the next section before running the final command. The Windows example invokes the virtual environment's Python directly, so activation is not required. You do not need to install anything globally.

texts, labels = zip(*examples)

# Stratify to keep both classes in the training and testing portions.
X_train, X_test, y_train, y_test = train_test_split(
    texts, labels, test_size=0.25, random_state=42, stratify=labels
)

# A simple baseline: always predict the most common class.
baseline = DummyClassifier(strategy="most_frequent")
baseline.fit(X_train, y_train)

# Pipeline prevents the text vectorizer from seeing held-out test messages.
model = make_pipeline(
    TfidfVectorizer(ngram_range=(1, 2)),
    MultinomialNB()
)
model.fit(X_train, y_train)

predictions = model.predict(X_test)
baseline_predictions = baseline.predict(X_test)
print("Training examples:", len(X_train))
print("Test examples:", len(X_test))
print("Baseline accuracy:", round(accuracy_score(y_test, baseline_predictions), 2))
print("Model accuracy:", round(accuracy_score(y_test, predictions), 2))
print("Confusion matrix (ham, spam):")
print(confusion_matrix(y_test, predictions, labels=["ham", "spam"]))
print(classification_report(
    y_test, predictions, labels=["ham", "spam"], zero_division=0
))

# Try two invented messages, not real personal or workplace email.
new_messages = [
    "Free reward claim your prize",
    "Can we meet on Friday for the report"
]
for message, predicted_label in zip(new_messages, model.predict(new_messages)):
    print(f"{predicted_label}: {message}")

What the code does: It keeps 25% of the labelled messages for testing, fits TF-IDF and Naive Bayes on the other 75%, compares against a majority-class baseline, then predicts labels for two new example messages.

04 / Read the results

Accuracy is not the whole story

Run the script and examine the printed scores. Accuracy is the proportion of correctly predicted test messages; the confusion matrix shows which classes were confused; precision describes how often a predicted class is correct, and recall describes how many actual examples of that class were found.

Because this dataset is tiny and uses deliberately repetitive phrases, the sample run may produce an unusually high test score—even 100%. That is not evidence that this model can safely filter real emails. A real evaluation needs representative data, more examples, deduplication, hard cases and checks for changes over time.

Important: Misclassifying a legitimate email as spam can be costly. A learning project must not silently delete, block or act on real messages. Keep a human in the loop.

Why compare against a baseline?

A model should improve on a simple starting point. Here, DummyClassifier always predicts the most common training label. If your trained model cannot improve on that baseline using appropriate evaluation data, adding complexity has not demonstrated value.

05 / Continue learning

Five ways to improve this project

  1. Collect better data: Use a properly licensed, de-identified dataset and document where it came from. Never upload private emails or credentials.
  2. Remove near-duplicates: Similar messages across training and testing can inflate scores.
  3. Study false positives: Inspect cases where legitimate messages are wrongly labelled as spam.
  4. Compare models: Try a linear classifier such as LogisticRegression with the same train/test split.
  5. Validate fairly: Use cross-validation for model selection and reserve a truly untouched test set for final evaluation.

06 / Common questions

Frequently asked questions

Does this need a paid AI API or GPU?

No. The project runs locally using free Python packages and a very small synthetic dataset.

Is this the same as training a large language model?

No. This is classical supervised machine learning, using numerical text features and a lightweight classifier.

Can I use this to protect a production email inbox?

Not as written. Real spam filtering needs extensive testing, security review, privacy controls, monitoring, suitable data and operational safeguards.
